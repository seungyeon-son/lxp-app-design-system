# 새 UI → 정식 컴포넌트 승격 규칙

시안을 만들다 보면 시스템에 없는 UI를 그 자리에서 만들게 됩니다(출석부의 출석 요약 카드, 출/지/결 버튼 등).
이 문서는 **그 UI를 언제, 어떤 기준으로, 어떤 절차로** `src/components/` 에 올리는지 정합니다.
README의 "확장하기"는 *방법*이고, 이 문서는 *판단 기준*입니다.

> 이 규칙은 첫 테스트 시안(출석부, 지금은 삭제함)을 분석해서 만들었습니다.
> 규칙마다 붙은 **근거**는 출석부에서 실제로 나온 문제입니다.

---

## 1. 세 단계

| 단계 | 어디에 | 이름 | 기록 |
|---|---|---|---|
| **시안 전용** | 시안 파일 `<style>` | 시안 접두사 (`att-`, `roll-`) — **`lxp-` 금지** | 시안 헤더 `@local-ui` |
| **후보** | 그대로 시안에 | 그대로 | 이 문서 §5 후보 장부 |
| **정식** | `src/components/*.js·css` | `lxp-*` 클래스 + PascalCase 함수 | README 컴포넌트 표, 쇼케이스 |

새로 만든 UI는 **무조건 시안 전용에서 시작**합니다. 시안을 그리는 도중에 `src/` 를 고치지 않습니다.
(시안 하나 때문에 공용 코드가 흔들리지 않게 하고, 실제로 반복되는지 확인한 뒤에 올리기 위해서입니다.)

**근거:** 출석부의 시안 전용 클래스 `att-*`, `roll-*`, `seg3`, `num` 은 모두 `lxp-` 와 겹치지 않아서
시스템 CSS와 충돌 없이 공존했습니다. 이 방식을 규칙으로 고정합니다.

---

## 2. 언제 올리나 — 승격 조건

아래 중 **하나라도** 해당하면 후보 장부(§5)에 올리고, 다음 작업자가 승격합니다.

| # | 조건 | 판정 |
|---|---|---|
| **A** | 같은 역할의 UI가 **서로 다른 시안 2곳**에 나왔다 | 두 번째 시안을 만드는 사람이 승격. 세 번째 복사는 하지 않음 |
| **B** | **한 시안 안에서** 같은 역할을 **다른 방식으로 두 번** 만들었다 | 후보 등록. 디자인을 하나로 정한 뒤 승격 |
| **C** | 시안 상태가 **확정**이 됐다 | 그 시안의 `@local-ui` 전부를 §3 기준으로 하나씩 판정 |
| **D** | Figma 컴포넌트 페이지에 그려졌다 | 즉시 승격(Figma가 원본) |

**근거 (B):** 출석부에는 "상태별 개수"를 보여 주는 UI가 두 개 있습니다. 학생 화면의 `att-legend`(점 + 회색 칸)와
교수자 화면의 `roll-count`(세로 구분선 + 색 숫자)입니다. 같은 정보인데 모양이 달라서, 다음 시안에서 또 세 번째
모양이 나올 가능성이 큽니다. 이런 경우 **승격보다 먼저 "하나로 정하기"** 가 필요해서 B를 따로 둡니다.

### 올리지 않는 것

- **화면 하나에만 의미가 있는 조합** — 예: `att-summary`(출석률 + 규칙 + 막대 + 범례를 묶은 카드).
  조합은 컴포넌트가 아니라 **화면 템플릿**입니다. 확정되면 `templates/screens.js` 에 화면으로 넣습니다.
  단, 그 안의 부품(막대, 개수 칸)은 따로 판정합니다.
- **기존 컴포넌트의 props 하나로 해결되는 것** — 새 컴포넌트를 만들지 말고 §4(빈틈 보강)로 처리합니다.

## 3. 승격 전 체크리스트

후보를 정식으로 올리기 전에 모두 통과해야 합니다.

1. **이미 있는가?** `src/components/`, `src/styles/base.css` 를 먼저 찾습니다.
   - 근거: 출석부의 `att-sec`(목록 위 소제목)는 홈 "이번 주 학습 6"의 섹션 제목과 역할이 같습니다(지금은 `Section` 함수).
     크기만 다릅니다(16B vs 20B). 새로 만들지 말고 기존 것에 `size` 를 추가하는 쪽이 맞습니다.
2. **도메인 이름을 뺐는가?** 함수 이름은 쓰임새가 아니라 모양·역할로 짓습니다.
   `seg3` → `ToggleGroup`, `att-bar` → `StackedBar`, `att-legend`/`roll-count` → `StatGrid`, `roll-week` → `PeriodNav`.
   출석 같은 도메인 의미(어떤 상태가 어떤 색인지)는 props(`items: [{label, tone, count}]`)로 넘깁니다.
3. **토큰만 쓰는가?** 색·글꼴·반경·그림자에 숫자를 직접 쓰지 않습니다. 쓰는 토큰이 **실제로 있는지** `src/styles/tokens.css` 에서 확인합니다.
   - 근거: `seg3` 의 `border-radius: 6px` 는 `--radi-2xsm`(6px)이 이미 있습니다.
   - 근거: 출석률 숫자의 `--font-head-32b` 는 모바일 정리 때 **삭제된 토큰**이라 16px 일반 글꼴로 렌더링됩니다(시안에서 실제로 깨져 있음). 가장 큰 제목은 `--font-head-28b` 입니다.
4. **기존 시각 언어와 맞는가?** 같은 종류의 기존 컴포넌트와 반경·그림자·여백을 맞춥니다.
   - 근거: 출석부 카드(`att-card`, `att-weeks`, `roll-list`)는 `--radi-md`(12px)인데, 기존 카드 3종
     (`CourseCard`, `DeadlineCard`, `ModuleItem`)은 모두 `--radi-lg`(16px)입니다. 정식 `Card` 로 올릴 때는 16px로 맞춥니다.
5. **터치 크기** — 반복해서 누르는 컨트롤은 높이 36px 이상을 권장합니다(시스템 최소는 `xs` 버튼 28px).
   - 근거: `seg3` 버튼은 34×28px로, 학생 수만큼 반복해서 누르는 컨트롤치고 작습니다.
6. **기존 함수 규칙을 따르는가?**
   - 인자는 객체 하나, 모든 값에 기본값(기본값만으로 Figma 기본 상태가 그려져야 함), 마지막에 `className = ''`
   - 반환은 HTML 문자열. 사용자 텍스트는 반드시 `esc()`, 자식 슬롯은 `slot()`
   - 클래스: `lxp-<이름>`, 요소 `__`, 변형 `--`, 상태 `is-`
   - 이미 쓰는 prop 이름을 재사용: `variant`, `size`, `tone`('info'|'neutral'|'posi'|'nega'|'warn'), `active`, `items`, `label`
   - 상단에 JSDoc(`@param`)과 Figma 노드 번호. Figma에 없으면 "토큰 기반 구성"이라고 적음
7. **인터랙션 상태를 마크업에 남기는가?** 눌림/선택은 `aria-pressed`·`aria-selected`·`is-active` 로 표현하고,
   이벤트 처리는 컴포넌트에 넣지 않습니다(컴포넌트는 순수 함수). 출석부 `seg3` 의 `aria-pressed` 방식이 기준입니다.

## 4. 빈틈(gap) 보강 — 새 컴포넌트가 아닌 경우

시안 헤더 `@gaps` 에 적힌 것은 **기존 컴포넌트가 못 해 줘서 우회한 것**입니다. 승격보다 가볍게, 바로 고쳐도 됩니다.

| 종류 | 규칙 |
|---|---|
| props 추가 | **선택 prop을 추가해서 기존 호출 결과가 바뀌지 않으면** 바로 고칩니다(하위 호환) |
| 아이콘 추가 | Figma에서 SVG를 내려받아 `src/assets/icons/` 에 넣습니다. CSS 뒤집기·회전으로 대신하지 않습니다 |
| 토큰 추가 | **Figma 변수에 있을 때만** `tokens/tokens.json` 에 추가합니다. 없으면 가장 가까운 토큰을 쓰고 `@gaps` 에 남깁니다 |
| 기존 동작 변경 | 다른 화면이 달라지므로 쇼케이스(`npm run dev`)의 모든 화면을 확인한 뒤 고칩니다 |

**근거:** 출석부는 아래 이유로 `lxp-btn`·`lxp-footer` 마크업을 직접 썼습니다. 시스템 클래스를 직접 쓰는 순간
나중에 컴포넌트 구조가 바뀌면 시안이 조용히 깨집니다. 그래서 "직접 마크업 = gap"으로 취급하고 기록합니다.

새 시안을 만들 때 이 표를 먼저 보고, 같은 역할의 UI가 있으면 **새로 만들지 말고 그 시안의 코드를 가져다 쓴 뒤 조건 A로 승격**합니다.
승격이 끝나면 줄을 "정식"으로 바꾸고 함수 이름을 적습니다.

## 6. 승격 절차

1. 후보 장부에서 해당 줄을 확인하고, 그 UI를 쓰는 **모든 시안**을 엽니다.
2. §3 체크리스트대로 **계층 폴더**에 컴포넌트 하나 = 파일 하나로 작성합니다(`docs/architecture.md`).
   - 더 쪼갤 수 없는 단위 → `primitives/`, 요소를 묶은 덩어리 → `blocks/`, 화면 구역 → `sections/`, 배치만 → `layout/`
   - 안에 버튼·칩·배지가 있으면 **다시 그리지 말고 아래 층 함수를 호출**합니다. 모양이 다르면 아래 층에 변형을 추가합니다.
   - `src/index.js` 에 export 를 추가합니다. 빌드 순서는 import 관계로 자동으로 정해지므로 `build.mjs` 는 고치지 않습니다.
3. README 컴포넌트 표(해당 계층), `docs/index.html` 쇼케이스에 추가합니다. 빠지면 `npm run build` 가 경고합니다.
4. 그 UI를 쓰던 시안의 로컬 코드를 정식 함수 호출로 바꾸고, 헤더 `@local-ui` 에서 지웁니다.
5. `npm test` — 새 컴포넌트는 "새로 생김"으로, 그 컴포넌트를 쓰게 된 화면은 "바뀜"으로 나옵니다. 바뀐 화면이 겉보기에 같은지 `npm run dev` 로 확인한 뒤 `npm test -- --update`.
6. 이 문서 §5 의 줄을 "정식 · `함수이름`" 으로 바꿉니다.
7. 커밋: `feat(component): StatGrid 추가 (출석부 att-legend·roll-count 통합)` — 어느 시안에서 왔는지 적습니다.
8. 디자인 시스템 아티팩트를 다시 게시합니다(CLAUDE.md "게시" 참고).
